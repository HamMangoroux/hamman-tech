LITTLE UPDATE

Alright so the reason I haven’t really been updating this blog is that I lost my secondary laptop’s password and the directory containing all the blog information was there so yeah pretty tragic. I’m now going to be updating this somewhat regularly though (hopefully). I know I already changed this project a bunch, but I just keep digging deeper into the OSdev rabbit hole and now I’m getting completely drawn to the idea of a riscv64 microkernel and working towards a working OS with a simple shell. Also, this article will just be a short update.

The gist of it

The gist of this project is to make a very minimal riscv64 microkernel with OPENSBI in the M-Mode and the microkernel in the S-mode, and have all the user drivers and all that in the U-mode. The goal of this is obviously still to be privacy focused, so I will still be trying to add as many security features as possible. I won’t be using AI for code generation because I mean, this is for learning.

What I’ve done so far

Not much. So far, I have the basics of risc-v down and currently skimming through OSTEP along with the xv6 book. I have set up the qemu environment and is starting to get some basics done. I’m still very much in the planning stage though, but I know I’ll need to go on high gear for this one because as much as I want to take my sweet time, college apps are right around the corner for me so I’ll have to keep that in mind. Of course, the enrichment of my understanding of low levle stuff is still the most important, but uh yeah I guess I’ll have to lock in and do it faster now lmaoo. Oh and I’m also first planning to make it single process just to get a single process working and then I’ll set up a queue system for multiple processes and I can’t even beging to think on how I’m going to implement simultanious processes. Really makes you think how crazy modern OSes really do. I think the short-term goal is to get a single process to work, because that’ll mean setting up memory, threads, and having places to put the input and output. Bascially, I’m not so sure myself yet, but I think the short term goal of a single process working is really nice because that’ll mean getting the resource allocation part done. I don’t think the queue system afterwards would be too hard?? but I guess we’ll have to see. Not seeing that far ahead for now.

Homework for me

  1. Actually start planning more comprehensively for the project.
  2. Work more on the project
  3. Update the blog more

Something a little extra

I recently got the CRAZYY ASSS OPPORTUNITY to do a mentorship?university? program (I don’t know what to call it), but basically some people at terasic will support me through an FPGA board project involving a TPU (or so I’ve been told). When I complete that project, I might combine the two projects together and run my riscv kernel on it or something. I’m completely unsure about this just yet, but maybe this is a possibility? Whatever ends up happening, I’m still really excited for the opportunity (honestly) and will be locking in on it. Yk it’s really funny cuz I thought there wasn’t any software under assembly and in turn machine code, but learning about FPGAs and Verilog and other HDLs, it’s just kind of blowing my mind at the endless opportunities. I think there is a debate whether HDLs are actually programming or software, but I personally think so from my very limited set of knowledge since you’re still compiling but with it being more physical than ever.
